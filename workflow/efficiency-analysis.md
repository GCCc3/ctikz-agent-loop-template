# Efficiency analysis workflow (human-initiated)

A separate workflow from the Generator-Reviewer loop. It reads what the loop
already produced, looks for work that repeats, and proposes generalisations —
principally dedicated MCP tools.

## Gate

- This workflow MUST be started only by explicit human instruction in a live
  session. It is never scheduled, never chained to an iteration, and never run
  as part of `workflow/coordinator.md`.
- One invocation performs one analysis pass over the archived iterations and
  stops. It may not start generation, review, rendering, or archival.
- Nothing this workflow produces changes the loop automatically. Every proposal
  is advice for a human; applying one is a separate, explicit decision.

## Inputs

Read-only, in full:

```text
iterations/iteration-*/transcripts/generator/*.md
iterations/iteration-*/transcripts/reviewer/*.md
iterations/iteration-*/results/*.json
iterations/iteration-*/manifest.json
current/reconstruction.tex
workflow/objective.md
workflow/completion-criteria.md
workflow/coordinator.md
workflow/generator-instructions.md
workflow/reviewer-instructions.md
scripts/, schemas/, .omp/agents/
```

Transcripts are the primary evidence: they hold the prompts, the tool calls, the
rework, and the corrections. Result JSON alone shows outcomes, not repeated
effort, so a pass that inspected only results is incomplete.

## One pass

1. Determine the reviewed scope. `scripts/next-iteration-number.sh` prints the
   number the next archive would take, so the highest archived iteration is that
   value minus one. The reviewed set is iterations `1..NNN`.

2. Delegate exactly one pass to the `efficiency` subagent. It must read every
   transcript in scope. It must not render, validate, edit, or archive.

3. Write the exact structured result to `tmp/efficiency-report.candidate.json`.

4. Persist it atomically:

   ```bash
   scripts/persist-result.sh \
     tmp/efficiency-report.candidate.json \
     analysis/efficiency-through-NNN.json \
     schemas/efficiency-report.schema.json
   ```

5. Render the human-readable report:

   ```bash
   scripts/render-efficiency-report.py analysis/efficiency-through-NNN.json
   ```

   Rendering is a pure function of the validated JSON, so the Markdown can be
   regenerated byte-identically at any time.

6. Preserve the analyst transcript beside the report, with the same front-matter
   fields used for iteration transcripts (`role: efficiency`, `agent`,
   `agentKind`, `agentStatus`, `scopeIterations`, `resultArtifact`, `source`):

   ```bash
   cat history://<agent-id> >> analysis/efficiency-through-NNN.transcript.md
   ```

   `history://` resolves only in a direct shell command, never inside a script.

7. Report to the human: the highest-leverage pattern, the tool proposals with
   their names and descriptions, and any open questions. State plainly that
   nothing has been applied.

## Evidence rules

- Every pattern needs at least two occurrences in distinct iterations, or at
  least three occurrences within one iteration.
- Every occurrence cites the iteration, the agent id, and the evidence (quoted
  phrase, command, or file reference).
- Patterns that fail the bar belong in `rejectedPatterns` with the reason, not
  in `patterns`.
- A missing or unreadable transcript is an evidence gap: set `status` to
  `partial` and name the gap. Do not fill it by inference.

## What makes a proposal a tool

A candidate is tool-shaped when a deterministic program could do the work:

- inputs are structured and identifiable (paths, coordinates, selectors);
- the computation is reproducible (measurement, diffing, arithmetic, lookup);
- the answer is a fact, not a judgement;
- the model currently re-derives it on every pass by reading and computing.

Excluded: re-wrapping an existing script with no new computation, and any step
whose answer is a judgement ("is this faithful enough?", "which symbol is
better?"). Those go to `nonToolRecommendations` or are rejected.

Every tool proposal states: a snake_case `name`, a one-sentence `purpose`, the
model-facing `description` (what it does, when to call it, what it returns, when
not to call it), typed `inputs`, the output shape, the pattern ids it retires,
the concrete savings, the risks, and a confidence level.

## Outputs

```text
analysis/efficiency-through-NNN.json            validated structured report
analysis/efficiency-through-NNN.md              rendered human-readable report
analysis/efficiency-through-NNN.transcript.md   analyst transcript for the pass
```

Re-running the workflow for the same reviewed set replaces that pair. Reports
for earlier reviewed sets are kept, so the history of the analysis stays
inspectable.

## Prohibited

- Never modify `iterations/`, `current/`, `workflow/`, `scripts/`, `schemas/`,
  or `.omp/` from this workflow.
- Never present a proposal as an applied change.
- Never weaken an evidence rule to produce a finding.
